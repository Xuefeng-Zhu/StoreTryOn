# Judging StoreTryOn

StoreTryOn is a **SPECS Lens prototype**, not a browser app. The verified walkthrough runs in Lens Studio SPECS Preview with labelled synthetic photos. Its live result is from a real YouCam Clothes V4 request. Physical SPECS camera, networking, hand tracking and device-session persistence remain unverified.

## Fresh clone and free UI walkthrough

1. Clone [Xuefeng-Zhu/StoreTryOn](https://github.com/Xuefeng-Zhu/StoreTryOn). If access is restricted, the entrant must supply repository access; no public instant-play access is implied.
2. Install Lens Studio 5.23.2 or newer and open `StoreTryOn.esproj`. Use the bundled compatible **Spectacles Interaction Kit 2.0.0, UIKit 2.0.0 and LEAF 2.0.2**. Keep those versions; newer package namespaces differ. If a vendor package must be restored, use Lens Studio's Asset Library and its applicable terms. Do not hand-edit generated `Cache/` files.
3. Set Preview to a SPECS device. Open the header's **Preview settings** and explicitly select **Use illustrations**. This editor-only mode needs no YouCam credential, makes **no provider request**, and labels its results as illustrative. It is the free UI walkthrough, not API proof. A fresh clone does not include the original machine's preview credential cache.
4. **Load sample photo → Use this photo → Shirt or Jacket → Load garment.** Inspect the review page; Retake and Back let you revisit it. Choose **Try it on** for the labelled illustration.
5. Review the result, choose **Add to shopping list**, then open the list and saved piece. **Try another item** retains the shopper photo for the visit. Test **Clear list → Keep items**, then the explicit clear confirmation if desired. Saved entries are bounded local JPEG thumbnails, not expiring provider links.

These sample photos are fictional and synthetic; see [fixture provenance](Assets/Samples/PROVENANCE.md). Loading a photo, opening the Lens or browsing does not start a paid generation.

## Optional real API walkthrough — consumes credits

Live mode requires an authorized YouCam account/key with available credits and a reachable protected HTTPS proxy. Hosting/account availability is not an access guarantee for a fresh clone. Coordinate demo access with the entrant or deploy a separate instance using [the backend instructions](Assets/Backend/README.md).

1. Use Node 22+ for `Assets/Backend/`. Inject `YOUCAM_API_KEY` and an independent randomly generated `STORETRYON_PROXY_TOKEN` of at least 32 characters through the host's secret manager. **Never place the provider key or a credential file in Lens assets, source, Inspector or Git.** The provider key is server-only.
2. Deploy behind HTTPS/TLS ingress. Start with `npm start`; the default process bind is `127.0.0.1:8787`. A container requires `HOST=0.0.0.0` and its assigned `PORT`. The Node process serves HTTP; expose it through the HTTPS ingress, not a public plain-HTTP port. The existing Dockerfile contains only runtime code.
3. In the local Lens, configure `proxyBaseUrl` to that HTTPS origin and `proxyAccessToken` to the **separate prototype token**, then select **Use live YouCam** in editor Preview settings. The editor can cache that proxy credential only for the matching HTTPS origin. Hardware needs its own configuration. Do not commit an authored credential field.
4. Load and review the sample shopper and garment. The review discloses that **Try it on sends the photos to YouCam and uses credits**. Only select it when authorized to spend those credits. Shirts map to `upper_body`; jackets map to `outer`.
5. Observe real sending/processing/loading stages, then **Generated by YouCam**. Save once and reopen the saved item. The client does not automatically repeat creation POSTs; interrupted read-only polling has bounded retries and same-job recovery.

The proxy token can be extracted from a Lens and is suitable only for controlled prototype access. It is not production user identity. Keep it private and rotate after the demonstration. The server keeps jobs/results in bounded temporary memory; local list clearing does not claim deletion of provider-held photos. Read the backend's limits and retention notes before live use.
