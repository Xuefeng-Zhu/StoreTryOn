# StoreTryOn SPECS design brief

## Approved product decisions

A shopper in a clothing store photographs a shirt or jacket, tries it on using their own photo, and adds it to a shopping list. Reuse the shopper photo for subsequent items during a visit. The list persists on the device until the shopper clears it. Every saved item includes the garment photo and generated try-on preview.

The target is a **SPECS Lens**, built in Lens Studio 5.23.2 from the genuine SPECS Base Template. All previous browser, IndexedDB, mobile web, phone-only UI, and web-testing plans are superseded. Implementation is explicitly authorized; no additional generic design sign-off is required.

## SPECS implementation defaults

The following are approved implementation defaults for the premium retail UI, rather than additional interview decisions. Their current verification status is recorded in [the premium UI matrix](../Assets/Evidence/premium-ux/README.md).

- Use a **44 × 54 cm movable UIKit Frame** with standard SIK hand interactions, white text, restrained mint accents, and photo-led cards. UIKit Flex/Grid layouts own spacing; show controls for the active page. The three main demo actions remain garment capture, **Try it on**, and **Add to shopping list**.
- Guide the shopper through separate **Your photo → Garment → Review → Creating your preview → Result** pages. Keep the brand, Back control, and shopping-list count in the header. Give each page one clear primary action and only the relevant secondary actions.
- For the shopper image, use the glasses' world camera to photograph the shopper's existing front-facing full-body photo displayed on another screen or as a print. This is a photo-of-a-photo input, not an unsupported glasses selfie camera. Review and retake it before continuing; reuse it for later garments in the visit. Keep this original shopper image in memory only for the visit.
- Select **Shirt** or **Jacket**, then photograph one unobstructed, front-facing, well-lit garment. Review the captured garment before Try it on; offer Retake and preserve the shopper image when trying another item. Invalidating an input must invalidate its old result.
- Keep generation source separate from input source. Editor sample photos carry a compact visible sample-input disclosure. Configured editor preview defaults to **live YouCam**; a processing/credit notice appears before the explicit Try it on action. Illustration mode is an explicit choice in **editor-only Preview settings**, visibly identified as not generated by YouCam and making no API requests. Preview settings and New visit controls do not appear as wearable shopper controls.
- Show live-service readiness before submission. An unavailable service disables the relevant start action and explains that try-on is temporarily unavailable. Opening the Lens, loading a photo, browsing, or switching pages must not start a generation request. Never silently replace a failed live call with an illustration.
- Report actual **sending photos → creating preview → loading preview** stages. Use an indeterminate activity indicator rather than a fabricated percentage or completion-time promise. Let the shopper browse the list while generation runs, retain the in-flight inputs, and offer a return to the pending/ready preview. Background completion must preserve the page the shopper is browsing.
- Present the generated image prominently on the result page, with the garment visible for comparison and the generation provenance stated. **Add to shopping list** appears only for a valid current result. Confirm a successful add, prevent duplicate adds from the same result, and offer **Try another item** while reusing the shopper photo.
- Browse saved items as **photo cards in a scrollable shopping-list collection**, then open a detail page showing that entry's garment and try-on photos. Retain category and generation/input provenance. Provide a useful empty state, loading feedback, and a return to capture or an in-progress try-on.
- Save encoded JPEG thumbnails and item metadata using Lens device-local persistent storage; do not depend on temporary result links. Saved previews contain the shopper's likeness. Bound saves by available space and the configured item limit, reject a save clearly when full, and never silently evict previous entries. If a stored list cannot be read, preserve it until the shopper explicitly resets it.
- Use an explicit **Clear list confirmation page** with **Keep items** and **Clear list** actions. Cancel preserves every entry. Confirm removes saved garment/result bytes and metadata while keeping the current visit's shopper image ready. Device/app data removal or uninstall may also remove storage. Local clearing does not claim deletion of provider-held files.
- Use action-specific recovery: recapture a failed photo, retry an eligible generation without losing its inputs, or retry a failed save without creating another preview. Preserve typed diagnostic codes for logs while keeping shopper-facing messages free of hosting or credential details.

## Main flow

1. **Your photo:** capture the shopper's displayed full-body photo, inspect it, retake if needed, then choose **Use this photo**. In editor preview, load the labelled synthetic shopper image. Reuse the chosen shopper photo for the visit.
2. **Garment:** choose Shirt or Jacket and capture one item. In preview, load the corresponding labelled synthetic garment. Review its photo and choose **Retake** or **Try it on**.
3. **Create the preview:** the explicit Try it on action sends the two photos to YouCam when live generation is selected and ready. Show genuine request stages and an indeterminate activity indicator. The shopper may open the list and return while the same job completes.
4. **Result:** view the try-on beside its garment reference and check its live/illustrative provenance. Choose **Add to shopping list**, see saved confirmation, then **Try another item** to return to garment capture with the shopper photo intact.
5. **Shopping list:** browse photo cards, open a saved garment/result pair, and navigate back without losing list state. A newly completed background try-on remains available to view; browsing does not save it automatically.
6. **Clear:** open Clear list, then choose **Keep items** or explicitly confirm **Clear list**. Confirmed clearing must stay empty after storage reload/preview reset; physical-device relaunch remains a separate required check.
7. **Preview settings, editor only:** explicitly choose live YouCam or illustrations, inspect readiness, or start a new preview visit. These choices never silently initiate processing and do not replace the SPECS hardware target.

## YouCam integration

Use Clothes V4: `upper_body` for shirts and `outer` for jackets. The jacket category layers outerwear over the existing outfit. A controlled HTTPS proxy owns the provider API key, registers and uploads images, creates and polls the task, and downloads the completed result. The Lens receives encoded image bytes rather than retaining an expiring provider URL.

The proxy uses a separate revocable access token for this prototype, bounded uploads/jobs/polling, and sanitized errors. This prototype token can be extracted from a Lens and must not be treated as a provider secret or a production identity system. A public release needs user authentication and operational abuse controls.

The preceding normal-editor UI verification proved that Try it on used the real API with sample photos when configured. Its separate demo credential is cached locally for the exact same proxy origin, independently of the shopping list, while the saved scene's credential field remains empty. The cache survived preview resets; no API request ran merely because the Lens started. [Normal UI verification](../Assets/Evidence/live-ui/README.md) records one real generation and save through the main hand controls on November 2. That history remains separate from the new premium retail layout, whose page transitions, recovery, and rendering checks are pending in [the current verification matrix](../Assets/Evidence/premium-ux/README.md).

The user supplied an external credential location during implementation; no provider key was copied into this project. Real backend requests succeeded for a shirt (`upper_body`, 16.52 seconds) and jacket (`outer`, 25.50 seconds), using synthetic input photos. Downloaded results and sanitized request-status evidence are in [Assets/LiveEvidence](../Assets/LiveEvidence/). A protected HTTPS proxy is now deployed on InstaCloud Free. Actual Lens `InternetModule` HTTPS/authentication and a live shirt upload/poll/decode passed in SPECS 27 preview, returning a 1024×1536 image in 14.973 seconds. The public URL is configured; the separate demo credential is kept outside saved source. Physical-device networking, camera capture, and the shopper's own photo remain unverified. See [network proof](../Assets/Evidence/network-preview/README.md) and [integration notes](youcam-integration.md).

| Criterion | Preview-checkable evidence | Device/live evidence required |
| --- | --- | --- |
| Capture a shirt or jacket and see the selected garment | Labeled simulated capture, category selection, review and retake | Glasses camera, real store lighting and image framing |
| Try it on using the shopper photo | State guards, shopper reuse, progress/error/retry, labeled sample result | Real YouCam request and generated result for both categories |

| Reopen and retain the list | Reconstruct storage and reset preview without clearing; verify encoded images | Quit and relaunch on physical SPECS, including offline re-display |
| Clear and remain empty | Cancel/confirm behavior, storage reload and preview reset | Quit/relaunch on physical SPECS |
| Spatial usability | Actual preview inspection, SIK controls, LEAF interaction/reach scenarios | Real hand tracking, comfort, panel placement and readability |
